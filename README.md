# The Body Mechanic — сайт студии

Сайт массажной студии The Body Mechanic (Дубай): главная с интерактивной 3D-моделью тела, запись на приём в 7 шагов, личный кабинет «Мои записи», каталог услуг, команда, журнал, контакты и два рекламных лендинга. Два языка: русский и английский.

## Состояние: что это и чем не является

- **Это фронтенд-прототип.** Он собирается в статические файлы и выкладывается как обычный статический сайт.
- **Бэкенда и базы данных нет.** Запись на приём, личный кабинет и заявки с лендингов работают на заглушках в браузере посетителя: запись нигде не создаётся, заявка с лендинга никуда не уходит, вход в кабинет ничего не проверяет.
- **Защиты от роботов нет.** Капча на шаге записи — заглушка, код из SMS не отправляется и не проверяется.
- **Содержимое — демо.** Цены, расписание, специалисты, статьи и фотографии — примеры; на страницах стоит пометка «Демо».
- **Сайт закрыт от поисковиков** (`robots.txt` с `Disallow: /`, `noindex` на каждой странице) и не подключён к счётчикам: контейнер GTM не задан.
- **Перед подключением контейнера GTM** с тегами Meta и Google Ads прочитайте [`docs/ANALYTICS-SEO.md`](docs/ANALYTICS-SEO.md), раздел 5. В выпуске RC-9 номер услуги попадал в адрес страницы записи (`/booking/?service=…`), а рекламные теги отправляют адрес сами; с выпуска RC-10 выбор в адрес не попадает. Убедитесь, что на живом сайте стоит RC-10 или новее ([`docs/CHANGELOG.md`](docs/CHANGELOG.md)).

Чтобы сайт начал принимать записи и заявки, нужен сервер. Контракт, по которому его ждёт фронтенд, и список того, что построить, — в [`docs/BACKEND-CONTRACT.md`](docs/BACKEND-CONTRACT.md).

Живой сайт: <https://bodymechanic-site.onrender.com> (Render, статический сайт, ветка `main`).

## Быстрый старт

Нужны Node.js 20.9 или новее (на Render — 22) и npm.

```bash
npm ci
npm run dev      # сервер разработки, http://localhost:3000
```

Сборка и просмотр в том виде, в каком сайт выкладывается:

```bash
npm run build    # статические файлы в out/
npm run serve    # раздаёт out/ по тем же правилам, что хостинг; порт: node scripts/gate-port.cjs
```

Переменные окружения для локальной работы не нужны. Полный список — в [`docs/CONFIG-DEPLOY.md`](docs/CONFIG-DEPLOY.md).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер разработки Next.js |
| `npm run build` | `next build` → `out/`, затем `scripts/fix-export-segments.mjs` и `scripts/lp-postexport.mjs` (зачем — в `docs/ARCHITECTURE.md`) |
| `npm run serve` | Раздаёт `out/` как хостинг: перезапись адресов записи, страница 404, заголовки кеша |
| `npm run lint` | ESLint |
| `npm run typecheck` | `next typegen` и `tsc --noEmit` |
| `npm run i18n` | Каждый ключ текста есть в обоих словарях; русский и английский словари совпадают по ключам |
| `npm run gate` | `i18n` и набор проверок Playwright против `out/`. Сначала нужна сборка |
| `npm run gate:clean` | Чистая сборка коммита в пустой папке, как её делает хостинг: `npm ci`, сборка, наличие ключевых страниц |
| `npm run test:matrix` | Расширенная матрица устройств и встроенные браузеры Instagram и Facebook |
| `npm run sync` | Инструмент команды-разработчика: копирует тексты и графику из соседних рабочих папок. В отдельной копии репозитория ничего не делает |

Для проверок Playwright нужны установленный Google Chrome и сборка WebKit: `npx playwright install webkit`. Подробности — в [`docs/TESTING.md`](docs/TESTING.md).

Порядок перед слиянием в `main`:

```bash
npm run lint && npm run typecheck && npm run build && npm run gate
npm run gate:clean
```

## Выкладка

Хостинг — Render, статический сайт. Пуш в ветку `main` запускает выкладку.

- Команда сборки: `npm ci && npm run build`
- Папка публикации: `out`
- Обязательная переменная: `NEXT_PUBLIC_SITE_URL` — адрес сайта без косой черты в конце. Без неё сборка на Render останавливается.
- Правила перезаписи адресов, заголовки кеша и защиты задаются в панели Render, а не в репозитории.

Всё о настройках, переезде на свой домен и открытии для поиска — в [`docs/CONFIG-DEPLOY.md`](docs/CONFIG-DEPLOY.md).

## Где править тексты

Все видимые строки лежат в `messages/ru.json` и `messages/en.json`. Это единственный источник текстов: в коде строк интерфейса нет. Наборы ключей в двух файлах должны совпадать, это проверяет `npm run i18n`.

Строки, которые начинаются с `TODO(content):`, — места, где ждут содержимого от студии. На экране вместо них стоит значок «Демо»; в исходном коде страницы сами описания остаются. Полный список и подробности — в [`docs/KNOWN-ISSUES.md`](docs/KNOWN-ISSUES.md), раздел 3.

## Стек

Next.js 16 (App Router, статический экспорт), React 19, TypeScript в строгом режиме, Tailwind CSS 4, next-intl, three.js с React Three Fiber, GSAP, Playwright. Точные версии — в `package.json` и в `docs/ARCHITECTURE.md`.

Файл `AGENTS.md` в корне создаёт и восстанавливает сам Next.js (`next dev`): в нём напоминание, что эта версия Next отличается от прежних и перед правками стоит читать документацию в `node_modules/next/dist/docs/`.
