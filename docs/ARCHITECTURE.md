# Архитектура

- Один Next.js-проект обслуживает страницы и публичный API каталога Altegio. Сборка находится в `.next/`, запуск через `npm run start`.
- **Базы данных пока нет.** Запись, «Мои записи» и заявки с лендингов работают на заглушках, которые исполняются в браузере посетителя (`src/lib/api/`, `src/lib/lp/bff-mock.ts`). Ни запись, ни заявка никуда не отправляются.
- Заглушки повторяют форму будущих серверных запросов. Список этих запросов есть в разделе «Чего здесь нет», подробный контракт — в `BACKEND-CONTRACT.md`.

## Что получается после сборки

`npm run build` запускает `next build`. Сборка пререндерит демостраницы. API и ссылки записи с произвольными ID обслуживаются во время запроса.

Предзагрузка шрифтов задаётся в раскладках через `PreloadFonts`. Сайт предзагружает один переменный Manrope, лендинги — четыре статических начертания с низким приоритетом. Файлы лежат в `public/fonts/v1/`. При замене файлов обновите версию адресов вместе с CSS и предзагрузкой.

`next.config.ts` сохраняет `images.unoptimized`, включает общую 404 и задаёт заголовки. `skipTrailingSlashRedirect: true` передаёт обработку завершающей косой черты в `src/proxy.ts`. Proxy ограничен префиксами `/ru` и `/en`. Он проверяет список страниц и шаблон ссылки на запись, затем отвечает HTTP 308 с каноническим путём и параметрами запроса. URL со слешем и неизвестные пути передаются маршрутизатору Next.js. Корневой адрес, API каталога и статические ресурсы вне префиксов локалей обслуживаются напрямую. При добавлении страницы проверьте список маршрутов в Proxy.

Что важно знать о маршрутах:

- **Списки демостраниц фиксируются при сборке.** Адреса разделов берутся из каталога-заглушки (`serviceSlugs`, `staffSlugs`, `articleSlugs` в `src/lib/api/index.ts`). Новая услуга появится на сайте только после новой сборки.
- **Несуществующий адрес** получает HTTP 404. Общая 404 (`global-not-found.tsx`) содержит оба языка: английский в разметке, русский в `<template>`, встроенный скрипт подставляет русский для адресов `/ru/…`.
- **Выбор, с которым приходят в запись.** Ссылки сайта (страница услуги, страница специалиста, его свободные окна, «Записаться снова») ведут на `/booking/` или `/booking/?step=2` и передают услугу, специалиста, день и время в момент нажатия через `sessionStorage['bm.bookingPreset']` (`src/components/booking/BookingLink.tsx`, `src/lib/booking/preset.ts`). Ссылка извне `/booking/?service=ID&staff=ID&date=ГГГГ-ММ-ДД&time=ЧЧ:ММ` работает: встроенный скрипт страницы записи перекладывает параметры туда же и убирает их из адреса до запуска приложения. Запись забирает выбор один раз (`src/components/booking/useBookingFlow.ts`). Зачем так — в `ANALYTICS-SEO.md`, раздел 5.
- **Шаг 1 записи** собран в статический HTML. Остальные шаги рисуются в браузере после чтения адреса. Чтобы шаг 1 не мелькал при прямой ссылке на шаг 2–7, встроенный скрипт прячет блок до готовности (`src/app/[locale]/booking/page.tsx`).
- **Лендинг** переключает вид формы параметром `?form=sheet` (кнопка открывает шторку) или `?form=hero` (форма на первом экране, по умолчанию). Это делает встроенный скрипт в `src/app/(lp)/[locale]/layout.tsx`.

## 3D-блок

Одна 3D-модель тела живёт на главной и на шаге 1 записи. Холст один на весь сайт: при переходе с главной в запись он не создаётся заново и модель не грузится второй раз.

### Как это устроено

1. **Постер.** В статическом HTML на месте модели стоит картинка-постер: `<picture>` с AVIF, WebP и PNG, 1350 × 1800 (`src/components/body3d/Body3DSlot.tsx`, пути в `src/lib/body3d/assets.json`). Постер — самый крупный элемент первого экрана на главной и в записи, по нему считается показатель LCP. На странице записи он дополнительно предзагружается (`src/app/[locale]/booking/page.tsx`).
2. **Провайдер и слот.** `Body3DProvider` стоит в раскладке сайта и держит один `<div>` для холста. Страница ставит `Body3DSlot` там, где нужна модель: в `src/components/sections/HeroAtlas.tsx` (режим `hero`) и в `src/components/booking/steps/StepZones.tsx` (режим `booking`). Провайдер переносит `<div>` с холстом в активный слот, а когда слота нет, прячет его (`src/components/body3d/Body3DProvider.tsx`).
3. **Когда грузится код 3D.** Не в первом экране и только на странице, где есть слот. Провайдер подключает `runtime/Body3DRuntime` динамическим импортом после события `load`, затем кадра отрисовки, затем простоя браузера (`requestIdleCallback`, предел 1,2 с).
4. **Проверка WebGL 2.** Если его нет, холст не создаётся и включается запасной режим (`src/components/body3d/runtime/Body3DRuntime.tsx`).
5. **Загрузка модели.** `loadModel` в `src/components/body3d/runtime/loader.ts`: `GLTFLoader` + `KTX2Loader` + `MeshoptDecoder`. Файлы моделей — GLB со сжатой геометрией (Meshopt) и текстурами KTX2. Декодер текстур (`basis_transcoder.js` и `.wasm`) лежит в `public/basis/`. Загруженная модель хранится в памяти страницы по адресу файла.
6. **Вторая модель.** После показа первой модели в простое подгружается модель другого пола, чтобы переключение пола не ждало сети (`src/components/body3d/runtime/Scene.tsx`).
7. **Отрисовка останавливается**, когда слот вне экрана, вкладка скрыта, включён 2D-режим или модель не нужна ни одной странице (`Scene.tsx`, `setFrameloop('never')`).

### Модели и уровни детализации

В `public/models/` четыре файла, в имени стоит хеш содержимого (`src/lib/body3d/assets.json`):

| Модель | LOD0 | LOD1 |
|---|---|---|
| мужская | `male.396bfdf6.glb`, 3 275 832 байта | `male.lod1.fdbdd47f.glb`, 1 977 928 байт |
| женская | `female.dab60a48.glb`, 3 525 424 байта | `female.lod1.2ea345c1.glb`, 2 083 652 байта |

LOD1 получают экраны шириной меньше 768 px и устройства, где `navigator.deviceMemory` не больше 4. Остальные получают LOD0 (`src/lib/body3d/lod.ts`).

### Качество и запасные режимы

- Плотность пикселей холста ограничена 2 (`Body3DRuntime.tsx`).
- Первые 3 секунды после показа модели измеряется частота кадров (`Scene.tsx`):
  - ниже 30 кадров в секунду — плотность не выше 1,5 и упрощённые материалы (`reduceMaterials` в `loader.ts`);
  - ниже 20 — запасной режим на главной и в записи. В полноэкранном просмотре снижается качество 3D.
- Модель не загрузилась за 15 секунд — статус `timeout`; ошибка загрузки — статус `error` (`Scene.tsx`).

Запасные режимы (`Body3DSlot.tsx`):

- **Запись:** 2D-схема тела (`src/components/body3d/Fallback2D.tsx`). Четыре SVG из `public/body2d/` (мужчина и женщина, спереди и сзади), логика выносок в `src/lib/body2d/body2d-callouts.mjs`. При ошибке показываются кнопки «Повторить» и «Перейти в 2D», при долгой загрузке — окно с выбором «Перейти в 2D» или «Подождать ещё».
- **Главная:** 2D-схемы нет, остаётся постер. Положение подписей зон берётся из заранее измеренной таблицы `src/lib/body3d/poster-anchors.json` (`src/components/body3d/usePosterAnchors.ts`).
- **Полноэкранный просмотр:** модель свободно вращается вокруг всех осей, выноски следуют за видимыми зонами по тому же механизму привязки, что и на главной. Если WebGL 2 недоступен или 3D-модель не загрузилась, остаётся постер выбранной модели.

На главной модель показывается только после того, как на постере дорисовались линии к подписям зон; страховка — 1 секунда после готовности модели (`src/lib/body3d/heroIntro.ts`).

### Состояние и зоны

- Общее состояние (пол модели, инструмент, метки, общая заметка, статус загрузки, режим 2D, качество) лежит в `src/lib/body3d/store.ts`. Это небольшое собственное хранилище без сторонних библиотек.
- Полноэкранный просмотр создаёт отдельный экземпляр хранилища. Выбор модели и подсветка зон хранятся в памяти страницы.
- Ограничения: не больше 10 меток, заметка к метке до 300 символов, общая заметка до 1000 (`store.ts`).
- Справочник зон: 18 зон, из них 13 парных (левая и правая), всего 31 ключ вида `knee_l`, `chest` (`src/lib/body3d/zones-meta.json`, чтение в `src/lib/body3d/zones.ts`). Номер зоны записан в вершины модели при её подготовке, поэтому порядок ключей в справочнике менять нельзя.
- Экранные координаты зон и меток для выносок отдаёт `src/lib/body3d/anchors.ts`.

### Отладка

Параметры адреса (в интерфейсе их нет): `?debug=nowebgl` (как без WebGL 2), `?debug=reduced` (сниженное качество), `?debug=lowfps` (как слабое устройство) — `Body3DRuntime.tsx`; `?debug=nointro` — `heroIntro.ts`.

Для тестов код выставляет объекты `window.__bm3d`, `window.__bmAnchors`, `window.__bmTextures` и `window.__bmHeroReveal` (`Body3DRuntime.tsx`, `Scene.tsx`, `loader.ts`, `heroIntro.ts`, `src/lib/body3d/anchors.ts`). И объекты, и режимы `?debug=` есть в сборке у каждого посетителя, а не только в тестах: что через них видно и почему они не убраны — в `KNOWN-ISSUES.md`, раздел 5, пункт 19 (находка Ж-8).

## Тексты и языки

- **Все видимые строки** лежат в `messages/ru.json` и `messages/en.json`: по 835 ключей в 26 разделах, набор ключей одинаковый.
- **Подключение:** `next.config.ts` → `src/i18n/request.ts`. Часовой пояс для дат и времени — `Asia/Dubai`.
- **Язык в адресе обязателен**, язык по умолчанию `en` (`src/i18n/routing.ts`). Серверной переадресации нет, потому что сайт статический.
- **Выбор языка на `/`** делает встроенный скрипт (`src/app/(root)/page.tsx`): сначала сохранённый выбор (`localStorage['bm.locale']` или cookie `NEXT_LOCALE`), затем язык браузера, иначе `en`. Без JavaScript страница уводит на `/en/`.
- **Переключатель языка** (`src/components/layout/LangSwitch.tsx`) — обычная ссылка на ту же страницу в другом языке с сохранением параметров и якоря. По клику он запоминает выбор.
- **Ссылки внутри сайта** пишутся без языка (`/services`), префикс добавляет `Link` из `src/i18n/navigation.ts`.
- **Тексты для клиентских компонентов.** Серверные компоненты берут строки через `getTranslations`. В браузер уходит только часть словаря:
  - раскладка сайта передаёт разделы `nav`, `footer`, `cookie`, `common`, `a11y`, `prototype`, `placeholder` (`src/lib/i18n/pickMessages.ts`, `src/app/[locale]/layout.tsx`);
  - страница добавляет свои разделы через `ScopeMessages` и `pickMessages` (`src/components/i18n/ScopeMessages.tsx`);
  - если клиентский компонент просит строку из раздела, который страница не передала, `next-intl` пишет в консоль ошибку об отсутствующем сообщении. Раздел нужно добавить в вызов `pickMessages` на этой странице.
- **Метаданные страниц** (заголовок, описание, canonical, hreflang, Open Graph) собирает `pageMetadata` в `src/lib/seo.ts` из раздела `meta.*`.

### Проверка текстов: `npm run i18n`

`scripts/check-i18n.mjs` проверяет три вещи и завершается с кодом 1 при любой проблеме:

1. каждый ключ, который код запрашивает как `t('…')`, есть в обоих файлах и указывает на строку, а не на раздел;
2. наборы ключей в `ru.json` и `en.json` совпадают;
3. `messages/*` и `src/lib/lp/config.json` совпадают с исходным набором текстов в соседней папке `../copy` (`scripts/copy-drift.mjs`).

Третья проверка **пропускается, если папки `../copy` нет**; скрипт пишет об этом строку в вывод. Ключи, собранные шаблонной строкой, скрипт только перечисляет (`--dynamic`).

### Откуда берутся файлы: `npm run sync`

`scripts/sync-assets.mjs` копирует в репозиторий материалы из соседних папок рабочего каталога разработки (`../copy`, `../3d`, `../design`, `../visuals`) и строит из них производные файлы. **Этих папок в репозитории нет.** Если рядом нет `../copy/messages.ru.json`, скрипт выводит «using committed copies» и завершается без изменений.

Что он создаёт, когда исходные папки есть:

Все эти файлы закоммичены, поэтому сборке соседние папки не нужны. Для команды, у которой есть только репозиторий, закоммиченные копии и являются исходниками: тексты правятся прямо в `messages/*.json`. Сами папки передаются отдельно по запросу (`KNOWN-ISSUES.md`, раздел 6). В файлах с полем `_source` написано «do not edit»: это относится к рабочему процессу с `sync`, которого без исходных папок нет.

Одно правило остаётся в силе всегда: декодер в `public/basis/` должен быть от той же версии `three`, что стоит в проекте. При обновлении `three` его нужно скопировать заново из `node_modules`.

## Стили и токены

- **Токены** (цвета, размеры шрифта, отступы, радиусы, тени, длительности) — CSS-переменные в `src/styles/tokens.css`. Там же ступени ширины контейнера: 768, 1024, 1440, 1920, 2560 px и правило для `prefers-reduced-motion`.
- **Tailwind 4** подключён в `src/app/globals.css` строкой `@import "tailwindcss" source(none)`; блок `@theme inline` связывает его тему с токенами. Обработчик CSS для Turbopack задан в `next.config.ts`. Вёрстка сделана своими классами из `src/styles/`: поиск типовых утилит Tailwind (flex, отступы, цвета темы) в `src/**/*.tsx` совпадений не дал.
- **Откуда Tailwind берёт классы.** Только из `src/` и `messages/`: автоматический поиск по проекту выключен (`source(none)`), источники перечислены строками `@source` в `globals.css`. Документы, тесты, скрипты и новые папки в поиск не попадают; чтобы добавить источник, его нужно назвать там же. Слово, похожее на класс, в словаре может добавить правило в CSS (`KNOWN-ISSUES.md`, раздел 5, пункт 21).
- **Только светлая тема:** `color-scheme: only light` в метаданных раскладок и в `globals.css`.
- **Шрифт** Manrope лежит в репозитории и подключается через `next/font/local`:
  - сайт — один переменный файл `public/fonts/v1/Manrope.woff2`, семейство `ManropeSite` (`src/styles/site-font.css`);
  - лендинг — четыре статических файла 400, 600, 700, 800 из `public/fonts/v1/`, семейство `ManropeLP` (`src/styles/lp.css`);
  - везде `font-display: optional`. Если Manrope не успел к первому кадру, страница остаётся на запасном шрифте. Метрики запасных шрифтов подогнаны в `src/styles/font-fallback.css`.

## Аналитика (коротко)

- До согласия посетителя в `window.dataLayer` ничего не пишется и ничего стороннего не грузится (`src/lib/analytics/track.ts`, `src/lib/analytics/gtm.ts`).
- После согласия на «Аналитику» или «Маркетинг» отправляется Consent Mode v2 и, если задан `NEXT_PUBLIC_GTM_ID`, грузится контейнер GTM. Без идентификатора события остаются в `dataLayer`.
- GA4 и Meta Pixel в коде не подключены: их настраивают внутри контейнера GTM.
- На сайте аналитику запускает `src/components/analytics/Analytics.tsx`, на лендинге — `src/components/lp/LpTracking.tsx`. Лендинг сразу убирает из адреса `utm_term` и `utm_content` (`src/lib/lp/attr.ts`).
- На страницах кабинета `/{locale}/account/…` аналитики нет: контейнер не загружается, события не пишутся, переход в кабинет и из него по любой ссылке делается полной загрузкой страницы (`src/lib/analytics/private.ts`, `src/components/layout/PrivateBoundary.tsx`).
- Ссылки «WhatsApp» и «Google Календарь» с текстом посетителя держат в разметке адрес без данных; полный адрес собирается в момент нажатия (`src/components/ui/PrefilledLink.tsx`).

Подробно — в `ANALYTICS-SEO.md`.

## Чего здесь нет

**Базы данных.** Услуги, цены, специалисты и статьи зашиты в сборку (`src/lib/api/mock-catalog.json`, `src/lib/api/mock-data.ts`). Специалисты — четыре карточки «Специалист студии N», статьи — три демо-статьи.

**Настоящей записи.** Шаги записи вызывают функции из `src/lib/api/index.ts`. Они не делают сетевых запросов и отвечают заранее заданными данными:

- свободные даты и время считаются по формуле;
- время 13:30 всегда «занято»;
- подтверждение возвращает одну и ту же демо-запись `9001`;
- капча — демо-токен, который появляется через 0,6 секунды (`useBookingFlow.ts`);
- код по SMS не отправляется (`postCode`), а шаг с кодом выключен флагом `NEXT_PUBLIC_BOOKING_SMS_REQUIRED`.

**Настоящего входа.** В «Моих записях» код не проверяется: после запроса кода любой непустой код открывает одни и те же три демо-записи (`src/components/account/Account.tsx`, `getAccountRecords`). Отмена и перенос меняют только `sessionStorage` вкладки.

**Приёма заявок с лендинга.** Форма вызывает `receiveLead` в `src/lib/lp/bff-mock.ts`. Заглушка проверяет поля и отвечает «принято». **Никуда ничего не отправляется.** То, что отправил бы сервер (сообщение в Telegram, событие Meta Conversions API, запись для Google Ads, комментарий для Altegio), собирается только в автотесте и отдаётся в его приёмник; у посетителя эти объекты не создаются, в `window` и в консоль ничего не попадает (`src/lib/lp/bff-mock.ts`, `src/lib/lp/lead.ts`, `src/lib/dev/test-hook.ts`).

**Интеграции с Altegio.** Есть только функция, которая собирает текст комментария к записи (`src/lib/altegio/formatComment.ts`).

**CMS.** Тексты страниц лежат в `messages/*.json`.

**Карты, оплаты, рассылок.** В коде их нет.

| `PATCH /api/account/records/:id` | `rescheduleRecord` | там же |
| `POST /api/lp/lead` | `postLead` → `receiveLead` | `src/lib/lp/lead.ts`, `src/lib/lp/bff-mock.ts` |

По замыслу, записанному в `src/lib/api/index.ts`, при подключении сервера меняются тела этих функций, а компоненты остаются как есть. Одно обстоятельство нужно учесть заранее: `getServices`, `getStaff`, `getArticles` и списки адресов вызываются ещё и при сборке. Каталог услуг, специалисты и статьи сейчас попадают в статический HTML, и обновить их без новой сборки нельзя.

### Режимы заглушки для проверки

Режимы работают **только в автотестах**: тест до загрузки страницы ставит крючок `window.__bmTest` (`src/lib/dev/test-hook.ts`, `testHook` в `e2e/helpers.ts`), приложение читает его один раз при загрузке модуля. У посетителя параметр `?mock=` ничего не делает. С крючком параметр `?mock=<режим>` на любой странице включает сценарий до `?mock=off` (`src/lib/api/mock-flags.ts`):

| Режим | Что происходит |
|---|---|
| `queued` | запись и заявка отвечают «принято в очередь» |
| `slot_taken` | первая проверка времени отвечает «занято» |
| `offline`, `server` | первый вызов каждого запроса падает с ошибкой сети или сервера, повтор проходит |
| `nodates` | свободных дат нет |

## Не подтверждено

1. **Как готовились модели GLB** (сжатие, запись номеров зон в вершины). В репозитории есть только готовые файлы; скрипт подготовки лежит в рабочей папке `3d/` вне репозитория и передаётся по запросу.
2. **Лицензия исходных 3D-моделей.** Модели взяты с сайта-прототипа клиента, как требует ТЗ (раздел 03); условия их использования командой не проверялись.
