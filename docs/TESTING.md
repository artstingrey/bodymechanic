# Тестирование

Источники: `playwright.config.ts`, папка `e2e/`, `scripts/`, `package.json`.

Команды проверки

| Команда | Что проверяет |
|---|---|
| `npm run lint` | ESLint (`eslint.config.mjs`) |
| `npm run typecheck` | `next typegen`, затем `tsc --noEmit` |
| `npm run i18n` | тексты: ключи и два языка |
| `npm run gate` | Словари, серверные тесты каталога, карточек главной и детальных услуг, сквозные тесты Playwright |
| `npm run test:catalog` | Контракт, ошибки, отсутствие утечек и ревалидация каталога в `next start` |
| `npm run test:home-services` | Карточки главной, RU/EN, состояния и карусель в Chrome на `next start` |
| `npm run test:home-team` | API сотрудников и секция команды в Chrome на `next start` |
| `npm run test:service-details` | API и страницы услуг RU/EN, HTTP 404, SEO, фото и запись на `next start` |
| `npm run test:service-staff` | Фильтр сотрудников по услуге, состояния блока, кеш и карточки RU/EN на `next start` |
| `npm run test:server` | HTTP-маршруты, канонические редиректы, приватные заголовки и шрифты в `next start` |
| `npm run test:matrix` | сквозные тесты на расширенном наборе устройств |
| `npm run gate:clean` | чистая сборка коммита, как на хостинге |

**Сколько тестов и сколько длится.** Полный `npm run gate` — 1209 тестов (выпуск RC-10, коммит `9c029a2`); в один поток он идёт 52 минуты. `npm run test:matrix` — 1268 тестов, около 22 минут в один поток. Итоги с датой и коммитом — в `QUALITY.md`.

## Что такое gate

Сначала выполните `npm run build`. Playwright поднимает новый `next start` для этой рабочей папки. Глобальная настройка проверяет `BUILD_ID` из локальной `.next/` по HTML ответа. Занятый порт останавливает прогон. Порт задаёт `GATE_PORT` или команда `node scripts/gate-port.cjs`.

При `GATE_BASE_URL=https://…` Playwright обращается к указанному сайту. Локальная сборка того же коммита нужна для инвентаря страниц и проверки публичных JS, CSS, HTML и RSC.

`npm run test:server` проверяет редиректы без автоматического перехода. Для страниц без слеша сверяются HTTP 308, путь в `Location` и параметры запроса. Отдельные запросы к страницам со слешем проверяют HTTP 200, а для кабинета также `Cache-Control: no-store` и `Referrer-Policy: no-referrer`. Корневой адрес, 404, `robots.txt`, `sitemap.xml` и шрифты проверяются напрямую. `test:catalog` проверяет прямой ответ API без `Location`.

`npm run test:catalog` всегда поднимает локальный production-сервер. Тестовый Node-процесс перехватывает серверный fetch к Altegio и использует синтетический fixture. Проверка состаривает свою запись кеша и перезапускает процесс. Серии из 12 параллельных запросов одной локали считают обращения к Altegio, записи Data Cache и диагностические ошибки. Тест проверяет выдачу предыдущего DTO, сохранение времени последней успешной записи, убывающий `Retry-After` на холодном кеше и обновление после паузы.

`npm run test:home-services` переиспользует тот же серверный fixture. Проверяет `Accept-Language`, отдельный кеш для каждой локали и его переиспользование главной и публичным API. Также проверяет приоритет текстов RU/EN и вывод исходного текста для нового ID, потоковую загрузку, пустой каталог, локальную ошибку с повтором, форматы цен, длительность и падение загрузки фото. Chrome проверяет карусель на 320/390/768/1280 px. Скриншоты сохраняются в `e2e/shots/home-services/`. Read-only сверка с реальным филиалом выполняется отдельно от автотестов.

После `npm run build` выполните `npm run test:home-team`. Серверный fixture подменяет `book_staff` и каталог услуг независимо. Проверяются DTO и ошибки API, дедупликация, общий кеш для API и секции, разделение локалей и ресурсов, ревалидация и последний успешный ответ при сбое. В Chrome проверяются независимая загрузка секций, повтор, фокус, анимация, фото и fallback, карусель RU/EN на 320/390/768/1280 px, свайп и клавиатура. Скриншоты сохраняются в `e2e/shots/home-team/`. Тест включён в `gate` и использует только синтетические данные.

`npm run test:team-list` использует production-сборку, Chrome и тот же синтетический `book_staff`. В RU и EN проверяет порядок и правила публикации, потоковую загрузку, пустой список, ошибку и повтор с клавиатуры. Проверяет подписи, портреты и заглушки, сетку на 320 и 1280 px, переход на канонический профиль и обратно, а также смену языка с сохранением ID профиля. Страница и публичный API используют общий серверный кеш, а браузер не запрашивает каталог напрямую.

`npm run test:service-details` использует ту же production-сборку и синтетический ответ Altegio. Проверяет канонические адреса, допуск новых ID без пересборки, статусы и `Retry-After`, общий кеш для API и страницы, восстановление после сбоя и отсутствие секретов в API, HTML, RSC и журналах. В Chrome проверяются оба языка, карточка услуги на 320 и 1280 px, запасное фото, переходы из списков и предзаполнение демозаписи.

`npm run test:service-staff` проверяет синтетический запрос `book_staff` с одним `service_ids[]`, отдельные списки и кеш для разных услуг и локалей, исключение скрытых и уволенных сотрудников, обработку `Retry-After` и отсутствие запроса при неразрешённом slug. Chrome проверяет ранний показ hero, загрузку, пустой список, ошибку и повтор с клавиатуры, порядок карточек, фото и заглушки на 390 и 1280 px. Read-only сверка филиала выполняется отдельно.

Общие настройки прогона (`playwright.config.ts`):

- язык браузера `en-US`, часовой пояс `Asia/Dubai`;
- предел на тест 60 секунд, на ожидание в проверке 10 секунд; отдельные тесты задают свой предел, самый большой — 20 минут (`e2e/hero.spec.ts`);
- параллельных потоков 4, с переменной `CI` — 2;
- при падении сохраняется снимок экрана.

## Проекты Playwright

Проект — это браузер с заданным размером окна. Каждый проект запускает только свои файлы тестов (`testMatch` в `playwright.config.ts`).

### Входят в `npm run gate` (14 проектов)

| Проекты | Браузер и окно | Файлы тестов |
|---|---|---|
| `w390`, `w768`, `w1280`, `w1920`, `w2560` | Chrome; 390×844, 768×1024, 1280×800, 1920×1080, 2560×1440 | `pages.spec.ts` |
| `flows` | Chrome, 1280×800 | `flows.spec.ts`, `states.spec.ts`, `seo.spec.ts`, `lp-tracking.spec.ts` |
| 8 проектов `A-*` (уровень A) | 4 iPhone в WebKit, 4 Android в Chrome | `mobile.spec.ts`, `lp.spec.ts`, `lp-tracking.spec.ts`, `hero.spec.ts`, `booking-compact.spec.ts` |

### Только в `npm run test:matrix` (22 проекта)

| Проекты | Браузер и окно | Файлы тестов |
|---|---|---|
| 18 проектов `B-*` (уровень B) | iPhone в WebKit, Android в Chrome | `layout-smoke.spec.ts`, `lp.spec.ts`, `hero.spec.ts`, `booking-compact.spec.ts` |
| 4 проекта `inapp-*` | встроенные браузеры Instagram и Facebook | `inapp.spec.ts`, `lp.spec.ts`, `lp-tracking.spec.ts` |

**Ловушка.** Если запустить файл тестов в проекте, куда он не входит, Playwright найдёт 0 тестов. Например, `states.spec.ts` есть только в проекте `flows`, а `layout-smoke.spec.ts` — только в `B-*`. Ноль найденных тестов не значит «всё прошло».

**Пропуски.** Часть тестов запланирована во всех проектах устройств, но выполняется на одном-двух: остальные пропускают себя сами через `test.skip` по имени проекта или размеру окна (`hero.spec.ts`, `lp.spec.ts`, `booking-compact.spec.ts`, `mobile.spec.ts`). Пропущенные тесты в отчёте — это норма.

### Браузеры

- **Chrome** — установленный в системе Google Chrome, а не сборка Playwright (`channel: 'chrome'`). На Windows он запускается с настоящей видеокартой (`--use-angle=d3d11 --enable-gpu`): 3D-модель рисуется как у посетителя. На других системах стоит флаг `--enable-unsafe-swiftshader`.
- **WebKit** — сборка Playwright, для проектов iPhone. Ставится один раз: `npx playwright install webkit`.

### Что тесты считают ошибкой сети

Правила собраны в функции `guard` (`e2e/helpers.ts`):

- любой запрос на чужой домен — ошибка;
- любой ответ со статусом 400 и выше — ошибка;
- отменённые запросы (переход на другую страницу оборвал загрузку) ошибкой не считаются, но каждый такой адрес запрашивается заново и должен ответить 200.

### `npm run test:matrix`

`scripts/test-matrix.mjs` выставляет `GATE_MATRIX=1` и запускает `playwright test --project=B-* --project=inapp-*`. Дополнительные аргументы передаются в Playwright. Если среди них есть свой `--project`, проекты по умолчанию не добавляются:

## Проверка текстов: `npm run i18n`

`scripts/check-i18n.mjs` завершается с ошибкой, если:

- код запрашивает ключ `t('…')`, которого нет в `messages/ru.json` или `messages/en.json`, или ключ указывает на раздел, а не на строку;
- наборы ключей в двух файлах различаются;
- тексты, настройки лендинга или список запрещённых слов расходятся с внешним набором в папке `../copy`. Эта проверка пропускается, если папки нет (см. ниже).

Ключи, собранные шаблонной строкой, скрипт не проверяет, а только перечисляет: `node scripts/check-i18n.mjs --dynamic`. Их ловят сквозные тесты: отсутствующую строку `next-intl` пишет в консоль как ошибку, а ошибка в консоли роняет тест.

## Чистая сборка: `npm run gate:clean`

`scripts/clean-build.mjs` отвечает на вопрос «соберётся ли на хостинге то, что закоммичено»:

1. выгружает коммит (`git archive`) в пустую временную папку системы; по умолчанию `HEAD`, другой коммит: `npm run gate:clean -- <ref>`;
2. сверяет тексты с папкой `../copy`, если она есть;
3. выполняет `npm ci` и `npm run build`;
4. запускает production-сервер и проверяет ключевые HTTP-маршруты, заголовки кабинета и предзагрузку шрифтов;
5. с RC-10: удаляет из временной папки `docs/` и `README.md`, добавляет слова, похожие на классы, в файл теста и в новый файл в корне, собирает ещё раз и сравнивает файлы стилей двух сборок побайтно. Если что-либо вне `src/` и `messages/` меняет CSS сайта, проверка падает (почему это возможно — `KNOWN-ISSUES.md`, раздел 5, пункт 21).

Незакоммиченные изменения в сборку не попадают: в этом смысл проверки. При ошибке временная папка остаётся для разбора, при успехе удаляется. Тесты Playwright эта команда не запускает.

## Как запускать локально

Нужны Node.js не ниже 20.9 и установленный Google Chrome.

```
npm ci
npx playwright install webkit     # один раз на машине

npm run lint
npm run typecheck
npm run build                     # обязательно перед тестами
npm run gate                      # тексты + все тесты
```

Частичные запуски:

```
npx playwright test --project=flows                    # один проект
npx playwright test e2e/seo.spec.ts --project=flows    # один файл в его проекте
npx playwright test --project=A-iphone-se -g "booking" # по названию теста
npx playwright test --workers=1                        # в один поток
```

Переменные задаются перед командой. В оболочке POSIX: `GATE_SHOTS=0 npm run gate`. В PowerShell: `$env:GATE_SHOTS = '0'; npm run gate`.

Советы:

- **Потоки.** Это наблюдение из прогонов, в коде его нет: тесты с 3D нагружают процессор и видеокарту, и когда на машине параллельно шло что-то тяжёлое, замеры в тестах первого экрана падали ложно. Помогал запуск в один поток (`--workers=1`).
- **Снимки.** `GATE_SHOTS=0` отключает снимки страниц в `pages.spec.ts` и ускоряет прогон.
- **Сервер в отдельном окне.** `npm run serve` поднимает тот же сервер на том же порту, Playwright его подхватит.

### Куда складываются результаты

Все четыре папки в `.gitignore`:

| Папка | Что в ней |
|---|---|
| `e2e/report/` | HTML-отчёт последнего прогона: `npx playwright show-report e2e/report` |
| `e2e/.results/` | рабочие файлы последнего прогона; следующий прогон их стирает |
| `e2e/.failures/<время прогона>/` | копии снимков, трасс и текста ошибки каждого упавшего теста (`e2e/keep-failures.ts`). Не стираются, удалять вручную. |
| `e2e/shots/<проект>/` | снимки страниц из `pages.spec.ts` |

Если указать свой `--reporter=…` в командной строке, сохранение улик отключится. Чтобы оставить его: `--reporter=line,./e2e/keep-failures.ts`.

## Что тесты читают вне папки `e2e/`

### Внутри репозитория

- `.next/` — инвентарь маршрутов и проверка публичных артефактов, `public/models/` — размеры GLB (`e2e/helpers.ts`, `e2e/flows.spec.ts`);
- `messages/ru.json`, `messages/en.json` — ожидаемые тексты;
- модули из `src/lib/` — каталог-заглушка, справочник зон, сборка JSON-LD, заглушка сервера (`e2e/seo.spec.ts`, `e2e/states.spec.ts`, `e2e/mobile.spec.ts`, `e2e/flows.spec.ts`).

### Вне репозитория

| Что | Кто читает | Что происходит, если этого нет |
|---|---|---|
| `../copy/messages.{ru,en}.json`, `../copy/lp-config.json`, `../copy/lexicon-denylist.json` — внешний набор текстов | `scripts/check-i18n.mjs`, `scripts/clean-build.mjs` | Сверка пропускается, в вывод пишется строка об этом. Остальные проверки идут полностью. |
| Google Chrome в системе | все проекты Chrome | Playwright не запустит браузер. |
| Сборка WebKit от Playwright | проекты iPhone | То же. |
| Временная папка системы и доступ к реестру npm | `scripts/clean-build.mjs` | Команда завершится с ошибкой. |

Путь `../copy` считается от корня репозитория: это соседняя рабочая папка команды-разработчика, в репозиторий она не входит (`KNOWN-ISSUES.md`, раздел 6). Ни одна проверка самого сайта от неё не зависит: список запрещённых слов лежит в `e2e/fixtures/lexicon-denylist.json`, и без этого файла `lp.spec.ts` падает, а не пропускает проверку.

Доступ в интернет самим тестам не нужен: любой запрос на чужой домен они считают ошибкой. Исключение — прогон с `GATE_BASE_URL` против выложенного сайта.

## Как тесты заглядывают внутрь заглушек

Проверки идут против той же сборки, что выкладывается на живой сайт. Поэтому у сборки нет «тестового режима», а есть один крючок (`src/lib/dev/test-hook.ts`):

- функция `testHook(page, { gtmId })` из `e2e/helpers.ts` до загрузки скриптов страницы кладёт объект `window.__bmTest`;
- приложение читает его один раз, при загрузке модуля. Объект, появившийся позже, не читается;
- через крючок тест разрешает режимы `?mock=…`, подставляет пробный идентификатор контейнера GTM и получает то, что собрали заглушки: тело заявки лендинга, сообщение администраторам, событие для Meta, комментарий записи. Приёмник складывает это в переменные самого теста: `__lpLastRequest`, `__lpBff`, `__lpLeads`, `__bmLastComment`.

Тест страницы посетителя крючок не ставит. Так проверяется, что без него `?mock=` ничего не делает и на странице не остаётся данных посетителя.

Что осталось в самой сборке вне крючка и доступно любому посетителю (находка Ж-8; `KNOWN-ISSUES.md`, раздел 5, пункт 19):

- параметр адреса `?debug=…` — режимы 3D для проверок: `nowebgl`, `reduced`, `lowfps`, `nointro` (`ARCHITECTURE.md`). Включаются ссылкой;
- объекты `window.__bm3d`, `window.__bmAnchors`, `window.__bmTextures`, `window.__bmHeroReveal` — состояние 3D-сцены. Первые два отдают и метки, которые поставил посетитель, с зоной каждой метки.

## Скорость первого экрана: метод MO-15

LCP первого экрана замеряли одним и тем же способом с 07.11.2026 (выпуски RC-4 … RC-8). Скрипт замера в репозиторий не входит (он лежит в рабочей папке команды и передаётся по запросу); метод воспроизводится любым инструментом с теми же условиями.

| Условие | Значение |
|---|---|
| Браузер | Google Chrome через Playwright, настоящая видеокарта |
| Окно | 390×844, мобильный режим с касаниями, плотность пикселей 3, строка браузера Pixel 7 |
| Движение | системная настройка «уменьшить движение» включена |
| Процессор | замедление в 4 раза |
| Сеть | задержка 150 мс, 1,6 Мбит/с вниз, 750 кбит/с вверх |
| Кеш | выключен, каждая загрузка холодная |
| Сервер | локальный `next start` |
| Что измеряется | LCP и CLS через `PerformanceObserver` |
| Сколько раз | не меньше трёх загрузок, берётся медиана |

Числа разных дней между собой не сравнимы: на одной и той же сборке медиана гуляла на 50 мс и больше. Две сборки сравнивают только чередованием в одной сессии: загрузка первой, загрузка второй, и так пять раз. Правило команды: разница медиан до 50 мс — шум.

Последний замер — 10.11.2026, выпуск RC-8 (`aabc4b1`) против RC-7 (`30307d4`), по пять загрузок:

| Страница | RC-7, медиана | RC-8, медиана | Разброс RC-8 | CLS |
|---|---|---|---|---|
| `/ru/` | 1496 мс | 1500 мс | 1388–1524 | 0 |
| `/ru/lp/a/` | 872 мс | 896 мс | 880–916 | 0 |
| `/ru/lp/b/` | 860 мс | 900 мс | 896–920 | 0 |

Элемент LCP на всех трёх страницах — изображение: постер модели на главной, фото первого экрана на лендингах. RC-9 этим методом не замеряли: первый экран он не меняет.

Это замер на рабочей машине в эмуляции, а не данные настоящих посетителей. Полевых данных нет: счётчики не подключены.

## Доступность

Отдельного инструмента проверки доступности (axe, Lighthouse) в репозитории нет. Что проверяют сквозные тесты:

| Что | Где |
|---|---|
| Один `h1` на странице, язык в `<html>` | `domChecks` в `e2e/helpers.ts`, через неё `pages.spec.ts`, `flows.spec.ts`, `layout-smoke.spec.ts` |
| Цели касания не меньше 44×44 px, шрифт полей ввода не меньше 16 px | там же; на лендингах `lp.spec.ts` |
| Контраст текста на лендингах по WCAG AA, включая состояния ошибки и «спасибо» | `lp.spec.ts`, функция `aaFails` |
| Фокус: на заголовке шага после смены шага, внутри диалога, возврат на кнопку после закрытия | `states.spec.ts`, `mobile.spec.ts` |
| Ошибки форм: текст у поля, сводка, фокус на первом поле с ошибкой | `states.spec.ts`, `lp.spec.ts` |
| 2D-схема тела с клавиатуры; объявления для программ чтения с экрана при работе с метками | `states.spec.ts`, `flows.spec.ts` |
| Увеличенный текст 130 и 200 % | `mobile.spec.ts`, `lp.spec.ts` |
| Системная настройка «уменьшить движение» | `hero.spec.ts` |
| Защита от принудительной тёмной темы браузера | `mobile.spec.ts` |

Чего в автоматических проверках нет: контраста на страницах сайта (кроме лендингов), прохода с программой чтения с экрана, проверки на настоящих устройствах. Ручные проверки, которые делала команда, в репозиторий не входят.
