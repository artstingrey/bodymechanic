## 3. Загрузка данных без связи с демо-букингом

Сейчас `HomePage` получает `[services, staff]` из `src/lib/api`; `services` используется дважды: в карусели и в `QuickForm` внизу. Поэтому нельзя просто заменить вызов `getServices` на live-функцию.

Целевое разделение:

- `HomeServices` вызывает новый server-only сервис для реального каталога;
- QuickForm продолжает получать прежний демо-набор до этапа реального букинга;
- команда и остальные секции сохраняют прежние источники;
- не вызывать из Server Component собственный HTTP `/api/catalog/services`: обе точки используют одну серверную функцию;
- не передавать в Client Components исходный Altegio-ответ, конфигурацию или токен. Карусель получает только необходимые карточки/props.

Предпочтительная схема — асинхронный Server Component внутри локального `Suspense`. Выбрать режим рендеринга страницы по [правилам этапа 1](../ALTEGIO-IMPLEMENTATION-PLAN.md#кеш-и-isr-для-следующих-этапов). `connection()` использовать только если нужен запрос во время обращения пользователя. Вызов размещать перед загрузкой и вне `catch`. Сборка должна проходить без CRM. Каталог не загружать из `generateStaticParams` и при импорте модуля.

Серверный кеш переиспользовать из этапа 1; не создавать отдельные таймеры и Map в секции. Ошибку каталога ловить локально, не делать её причиной ошибки всей главной и не блокировать Hero/3D и остальные блоки ожиданием ответа CRM.

## 4. Состав, порядок и редакционные поля

Для первого подключения выводить все услуги, которые общий адаптер признал опубликованными для онлайн-записи; сохранять порядок ответа. Не брать первые N элементов без объяснения и не включать только зашитую smoke-услугу.

При наличии утверждённого списка основных услуг использовать явные реальные ID в конфигурации главной. Формат должен различать «ограничить список» и «изменить порядок», чтобы новая услуга не терялась случайно. Проверять ссылки конфигурации на отсутствующие ID и дубликаты. Не определять связи с помощью сравнения русского/английского названия или индекса карточки.

Контент по умолчанию:

1. Название — реальное из DTO. Подтверждённый редакционный перевод по ID имеет приоритет для нужной локали. Если его нет — оригинальное название, без выдуманного русского аналога и без машинного перевода на каждом запросе.
2. Краткое описание — утверждённое по ID или безопасное публичное описание DTO. При отсутствии не показывать абзац; не подставлять описание похожей демо-услуги.
3. Не вставлять сырой HTML через `dangerouslySetInnerHTML`. Внешнее поле `comment` нельзя автоматически считать публичным описанием.
4. Не смешивать операционные цены с редакционной конфигурацией. В файле главной допустимы переводы, порядок и медиа, но не второй источник стоимости.

## 5. Цена, длительность и изображения

### Цена

- Равные min/max — конкретная цена, без необоснованного «от».
- Различающиеся известные min/max — диапазон.
- Известна только минимальная цена — «от …».
- Отсутствующая цена — нейтральное «Стоимость уточняется» в RU/EN; не отображать `0` или `NaN` вместо неизвестного значения.
- Настоящий ноль не превращать в отсутствие данных через truthy-проверку. Специальные условия нулевой цены/«по запросу» должны быть подтверждены настройкой услуги.
- Валюта — из согласованного DTO/проверенной конфигурации филиала. Если она неизвестна, не приписывать AED; показать нейтральное состояние стоимости.
- Не применять оффер LP −20% к этим карточкам и не рассчитывать повторно скидку поверх уже полученной цены.

### Длительность

Показывать только известное нормализованное значение. При отсутствии убрать поле длительности либо использовать согласованную нейтральную строку; базовое решение — убрать. Не делать отдельный запрос для каждого сотрудника ради цифры на главной. 100 минут — обычная длительность, а не автоматически «до 1 ч 40 мин».

Создать нейтральный форматтер или расширить существующий с явным режимом данных, сохранив старое поведение немигрированных страниц. Нельзя снять демо-плашки и поменять формат сразу у всего каталога/кабинета побочным изменением общей функции.

### Фото

Приоритет: валидное опубликованное изображение услуги → явно сопоставленная утверждённая локальная иллюстрация → нейтральный placeholder. Не назначать локальные фотографии по индексу или случайному slug.

Для локальной иллюстрации сохранить подпись «Иллюстративное фото». Для изображения из CRM не добавлять её автоматически и не объявлять фотографию подлинной съёмкой студии без основания. У картинки — содержательный alt, стабильное соотношение сторон 4:5 и отложенная загрузка вне первого экрана.

Учесть битый URL и ошибку загрузки, а не только `imageUrl: null`. Если нужен обработчик `onError`, выделить небольшой клиентский компонент изображения; не превращать всю страницу в Client Component. Для внешних источников проверить настройки изображений/CSP и сетевые проверки тестов; не отключать все ограничения внешних запросов.

## 6. Ссылки во время частичного внедрения

На этом этапе `/services`, `/prices`, `/services/[slug]` и формы ещё демонстрационные. У реального каталога пока нет гарантированной связи с реальной страницей услуги.

Поэтому временно:

- реальные карточки — информационные, без перехода в демо-деталку и без перехода к созданию демо-записи;
- в секции не показывать кнопку «Все услуги» до этапа миграции каталога;
- для варианта без `href` не рендерить пустой `<a>`, `href="#"`, стрелку перехода, ложный pointer cursor или клавиатурный фокус как у ссылки;
- не генерировать slug из названия и не направлять все карточки на одну услугу;
- действующие потребители `ServiceCard` с href сохраняют своё поведение;
- внешний вид карточек, фотографии, типографика, данные и карусель остаются прежними по стилю.

Ссылки и кнопку возвращает этап 3 после проверки реальных маршрутов. Если пользователь отдельно изменит это решение, зафиксировать новый вариант в общем плане; не подменять его скрытым расширением scope.

## 7. Состояния и визуальное поведение

**Загрузка:** локальный skeleton/стабильный блок без выдуманных названий и цен. Остальная главная отображается независимо.

**Успех:** данные только нового каталога, без плашки «Демо» у реальных цен. Общая маркировка прототипа пока остаётся, поскольку букинг и другие разделы ещё на заглушках.

**Пустой каталог:** отдельный спокойный текст, карусель и стрелки не создаются. Пустой ответ не считается сетевой ошибкой и не заполняется mock-карточками.

**Ошибка:** сообщение только внутри секции и доступная повторная попытка. Повтор обновляет server-rendered данные (например, `router.refresh()` из небольшого клиентского элемента); не создаёт второй источник каталога и не вызывает циклический polling. Ошибка без доступных данных не должна отображаться как успешное отсутствие услуг.

**Медленный ответ и повтор:** проверить, что MotionRoot не оставляет добавленные элементы невидимыми, Carousel правильно измеряет размеры, фокус не теряется, а повторная попытка не вызывает hydration warning. Не добавлять глобальные анимационные изменения без обнаруженной необходимости.

## 8. Проверки и критерии завершения

Детерминированные тесты выполняются через серверный механизм, подготовленный этапом 1. `page.route('/api/catalog/services')` сам по себе не перехватит прямой запрос Server Component к серверному сервису.

Проверить:

- RU/EN: заголовок, подписи, названия и fallback языка;
- один элемент, несколько, пустой список; длинное название и отсутствие описания;
- фиксированную цену, диапазон, минимальную цену, ноль, неизвестную цену/валюту;
- известную/неизвестную длительность и отсутствие демо-правила для 100 минут;
- CRM-изображение, локальную иллюстрацию, отсутствие и ошибку изображения;
- loading, ошибку, повтор, медленный ответ; остальная главная продолжает работать;
- swipe, стрелки и клавиатуру; ширины 320/390, 768 и 1280+;
- отсутствие переходов на выдуманные/демо-деталки из новой секции;
- QuickForm, команда, каталог и LP не получили реальные ID и не изменили сценарии случайно;
- браузер не обращается к Altegio API и не получает токены; реальные карточки находятся в server-rendered содержимом после загрузки.

Выполнить lint/typecheck/i18n/build, целевые интеграционные и визуальные проверки на Node-приложении. Read-only live smoke при доступной конфигурации подтверждает соответствие карточек каталогу филиала; запись для этого не создавать.

Готовность этапа: только целевой блок показывает реальные услуги, сохраняет оформление, имеет честные состояния и корректные значения, не ломает соседние части и не ведёт пользователя в ложную запись. В итоговом отчёте перечислить оставшиеся зависимости: страницы услуг/каталог, команда, реальные формы, переводы/медиа, которые ещё не предоставлены.
