# 7.2. Профили специалистов и окна на сегодня

Канонический адрес реального профиля — `/{locale}/team/staff-<id>/`. Общий каталог сотрудников даёт имя, портрет, должность и специализацию для страницы, metadata и JSON-LD. Отсутствующий или снятый с публикации профиль возвращает 404. При сбое каталога профиль показывает сообщение с повтором. Старые адреса `specialist-*` также рендерятся по запросу и используют демоданные.

Окна загружаются отдельно через `GET /api/booking/staff-today?staffId=<id>&locale=<locale>`. Сервер сначала вызывает `book_staff_seances` без услуги. При неподдерживаемом запросе или неверном формате ответа он получает список услуг сотрудника через `book_services` с `staff_id` и последовательно запрашивает `book_times` на текущую дату. Валидный пустой результат показывается сразу. Ответ окна имеет `Cache-Control: no-store`, а пауза после 429 следует `Retry-After`. После фильтрации по времени начала и текущему дню в Дубае остаётся не более четырёх самых ранних разных окон.

Chrome на production-сборке с синтетическим Altegio подтвердил RU/EN, redirects и canonical, хлебные крошки, переключение языка, фото и его заглушку, 404 и сбой каталога, независимую загрузку окон, сортировку, пустой список, ответ только на завтра, границу суток в Дубае, повтор после ошибки и 429, а также запасной запрос. Для повтора запустить `npm run test:staff-profile` после сборки. GET-сверка с филиалом остаётся открытой, так как в окружении для проверки не было настроек Altegio.

Для 7.3 использовать `catalogStaffSlug(id)` и поля `datetime` и `time` из API окон. Для предвыбора конкретной услуги в запасном сценарии понадобится передать её ID из серверного результата. Переходы из карточек услуг и запись с реального профиля входят в 7.3.
