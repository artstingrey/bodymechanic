# Задание этапа 8. Каталог услуг и фильтры по категориям

**Статус — завершено.** Реализация и результаты проверок описаны в [плане интеграции](../ALTEGIO-IMPLEMENTATION-PLAN.md#этап-8-каталог-услуг-и-фильтры-по-категориям).

Подключить реальные услуги и категории Altegio на `/ru/services/` и `/en/services/`. Использовать текущую страницу `/ru/services/` как шаблон для заголовка, сетки карточек и фильтров. Объём задачи охватывает страницу списка услуг и её переходы. Страница «Цены», главная, профили и букинг относятся к отдельным задачам.

Перед работой прочитать `AGENTS.md`, [план интеграции](../ALTEGIO-IMPLEMENTATION-PLAN.md) и [задание детальных страниц](04-altegio-service-details.md). Перед правками Next.js сверить документацию установленной версии и Context7. Файлы `.env` не открывать. Сверять филиал только GET-запросами через уже настроенное окружение.

## 8.1. Подключить реальные услуги и категории

- Заменить `getServices` и `getCategories` из демокаталога на прямой серверный вызов `getCatalogServices(locale)`. Переиспользовать публичный DTO, серверную конфигурацию и кеш каталога с ревалидацией 14400 секунд. Сборка должна проходить без доступа к CRM. [Страница списка](../../src/app/%5Blocale%5D/services/page.tsx) · [Серверный каталог](../../src/server/catalog/services.ts) · [Публичный DTO](../../src/lib/contracts/catalog.ts)
- Сохранять порядок услуг и категорий из ответа. Связывать услугу с категорией по `categoryId`. Полный список включает услуги без категории и услуги, чья категория отсутствует в ответе. Подготовить данные для фильтров из реальных `id` и `title`, общих по идентичности для RU и EN. Название категории брать из ответа для текущей локали. Сохранять отличие пустой категории от некорректной ссылки на фильтр.
- Подключить загрузку данных к текущей странице. Различать состояние загрузки, успешно полученный пустой каталог и временную ошибку с повтором. При недоступности CRM использовать существующее поведение кеша, а при отсутствии доступного результата показывать состояние ошибки. Достаточно необходимых изменений `ServiceList`, чтобы отобразить реальные данные без демонстрационных цен, карточек и ID. Полное оформление карточек и проверка навигации фильтров входят в следующие части. [Текущие карточки и фильтры](../../src/components/services/ServiceList.tsx)

**Приёмка.** На production-сборке с синтетическим upstream проверить получение реальных категорий и услуг в RU и EN, порядок, отсутствие категории, пустой каталог, ошибку и восстановление через повтор. Сборка проходит без CRM. Браузер получает данные от сайта, а запросы к Altegio выполняет сервер.

## 8.2. Заполнить карточки услуг

- Сохранить сетку и существующий `ServiceCard`. Использовать правила главной по реальному ID для заголовка и описания. RU предпочитает текст Altegio и дополняет пропуски редакционным текстом. EN использует редакционный текст при наличии. Для новых услуг использовать текст каталога. [Секция услуг на главной](../../src/components/sections/HomeServices.tsx) · [Редакционные данные по ID](../../src/content/home-services.ts)
- Форматировать цену общим форматтером с валютой из DTO. Проверить ноль, точную цену, нижнюю границу, диапазон и неизвестную стоимость. Длительность выводить при наличии. Для фото использовать публичный HTTPS-адрес, утверждённую иллюстрацию по реальному ID или существующую заглушку. Неудачная загрузка также ведёт к заглушке. [Форматтер цены](../../src/lib/catalog-service-price.ts) · [Компонент фото](../../src/components/sections/HomeServicePhoto.tsx)
- На каждой карточке использовать канонический адрес из `catalogServiceSlug(id)`. Контрольная ссылка — `/ru/services/sports/`. Для услуги без закреплённого slug использовать действующий `service-<id>`. [Правила URL услуг](../../src/lib/catalog-service-slugs.ts)

**Приёмка.** Проверить RU и EN, мобильную и широкую сетку, длинные заголовки, неполные данные, фото и переход на страницу той же услуги. Сверить название, цену и длительность с главной и детальной страницей.

## 8.3. Подключить и проверить фильтры

- Сформировать кнопки из категорий Altegio и добавить «Все услуги». Использовать `?category=<id>` с положительным ID категории. Выбранная категория фильтрует карточки по `categoryId`, имеет активное состояние, а счётчик отражает число видимых карточек. Известная категория без услуг показывает пустое состояние. Отсутствующий, некорректный или неизвестный ID открывает «Все услуги».
- Для прежних `?category=massage` и `?category=rehab` применять фильтрацию только при подтверждённом соответствии реальному ID. При отсутствии подтверждённой привязки открывать «Все услуги». Проверить переходы с прямой ссылки, смену категории, «Все услуги», обновление, кнопки браузера «Назад» и «Вперёд» и смену RU/EN с сохранением выбранной категории.
- Провести сквозную проверку маршрута от кнопки «Все услуги» на главной до категории, карточки и канонической детальной страницы. Использовать синтетические категории с разными ID, одним пустым разделом и услугой без категории. При доступном филиале сверить состав и порядок без записи в CRM.

После каждой части указать изменённые точки входа, пройденные проверки и оставшиеся зависимости. Для правок запускать `lint`, `typecheck`, `i18n` и целевые проверки на production-сборке. После 8.3 записать итог в общий план и отметить поведение старых ссылок на категории.
