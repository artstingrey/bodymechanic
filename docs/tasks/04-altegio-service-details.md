# Задание для чата 4. Детальные страницы услуг Altegio

**Статус:** подготовлено к реализации. Этапы 1–3 завершены. Исходная точка для постановки — `c5688de`.

Подключить детальные страницы `/{locale}/services/{slug}/` к публичному каталогу Altegio на примере `/ru/services/sports/`. Выполнить последовательно две части. В первой подготовить общий серверный загрузчик, API и заполнить `svc-hero`. Во второй подключить сотрудников выбранной услуги в секции `doc-sections__wide`. Проверить каждую часть на production-сборке. Контрольный адрес для EN — `/en/services/sports/`.

Объём этапа ограничен детальными страницами. Миграция списков `/services` и `/prices`, замена ссылок в секциях главной, страницы `/team`, расписание, запись, QuickForm, кабинет, лендинги и наполнение остальных редакционных секций идут отдельными задачами. Сохранить общий статус деморежима и закрытую индексацию.

Сохранить существующую разметку, секции, кнопки и визуальные элементы. Если целевой маршрут ещё не подключён к реальным данным или переход передаст их в демосценарий, оставить элемент видимым в том же месте и с тем же текстом. Временно вывести его без `href` и без действия по нажатию. Это касается кнопки записи в `svc-hero` и ссылок на профили реальных специалистов. Рабочие переходы сохранить.

Страницы, JSON-LD и список известных адресов сейчас зависят от демокаталога. У `sports` есть исходная двухколоночная сетка `.doc-sections`, где блок специалистов занимает полную ширину.

Использовать серверную конфигурацию и синтетический upstream для тестов. Файлы `.env` и архив `bodymechanic-site-main.zip` не открывать. Проверку филиала выполнять только через уже настроенное окружение и только на чтение.

## Часть 1. Серверная основа, API и `svc-hero`

### Адреса и получение данных

1. Разрешать публичную услугу по стабильному slug. Для проверенных соответствий явно закрепить `ID → slug`. Сохранить `13982355 → sports`. Эта услуга уже связана с «Спортивным массажем» в `home.services.cards` обоих словарей. Сверить привязку с публичным каталогом, если доступно настроенное окружение. Для услуги без закреплённого slug использовать `service-<id>`. Привязки одинаковы для RU/EN. Проверить уникальность slug и ID. Переименование услуги в CRM сохраняет адрес, поскольку slug определяется закреплённой привязкой или ID.
2. Сохранить работающие переходы из `/services` и `/prices` на период их миграции. `/ru/services/sports/` и `/en/services/sports/` сохраняют свои адреса и начинают показывать реальную услугу Altegio. Несопоставленный старый адрес, например `/ru/services/lfk-kinesio/`, продолжает открывать демонстрационную страницу до подтверждения соответствия или миграции списков. При сбое CRM показать состояние ошибки на реальном адресе. Если услуга отсутствует в успешно загруженном каталоге, вернуть 404. Для каждой реальной услуги использовать один канонический путь. Если у услуги закреплён редакционный slug, перенаправить её альтернативный `service-<id>` на канонический путь или отвергнуть его последовательно в API и на странице.
3. Добавить `GET /api/catalog/services/[slug]?locale=ru|en`. Предлагаемый контракт успешного ответа — `{ data: { service, category }, meta: { source: 'altegio', locale } }`. `service` расширяет `CatalogService` каноническим `slug`, `category` содержит публичные `id` и `title` либо `null`. Зафиксировать, что API возвращает нормализованные поля каталога, а редакционное представление RU/EN применяется согласованно к видимой странице, metadata и JSON-LD. Локаль по умолчанию `en`, повторные и лишние query-параметры отклоняются с `400 INVALID_QUERY`. Подтверждённое отсутствие публичной услуги возвращает `404 SERVICE_NOT_FOUND`. Другие ошибки используют текущий формат каталога, включая `Retry-After` при ограничении Altegio. Сохранить `Cache-Control: no-store` на HTTP-ответах и кеш общего DTO на сервере.
4. Страница и метаданные обращаются к общему серверному загрузчику напрямую. Переиспользовать результат поиска в пределах рендера и кеш каталога между запросами. Убрать зависимость реальных detail-адресов от `dynamicParams = false` и демосписка в `generateStaticParams`. `npm run build` должен проходить без CRM, новые услуги должны открываться по запросу без пересборки. Проверить варианты адреса со слешем и без него, сохранение query при редиректе и фирменный HTTP 404 на неизвестном slug. Next.js сохраняет HTTP 200 у уже начатого streaming-ответа, поэтому разрешить услугу до отправки разметки и подтвердить статус прямым HTTP-тестом. Допустима генерация по запросу с кешем данных. Если используется ISR страницы, проверить, что временный сбой или холодный кеш не закрепляют ошибочную страницу на четыре часа. [Документация Next.js 16.4.5 по `generateStaticParams`](https://github.com/vercel/next.js/blob/v16.4.5/docs/01-app/03-api-reference/04-functions/generate-static-params.mdx)

### Содержимое страницы

- Сохранить `svc-hero`, его порядок на мобильных и десктопе, хлебные крошки и существующие компоненты фото. Заполнить название, категорию, краткое описание, цену, длительность и фото там, где данные доступны. Для названия и описания применить текущие правила `HomeServices` по ID. RU берёт данные CRM и дополняет пропуски редакционными текстами, EN предпочитает существующие редакционные тексты. При наличии нескольких вариантов локализация страницы и подписи должны совпадать.
- Цена использует подтверждённую валюту и форматирование реального каталога. Сохранить ноль, точную цену, диапазон и нижнюю границу. Если цена или валюта неизвестна, показать существующее нейтральное сообщение. Если длительность отсутствует, сохранить её поле в разметке и оставить значение пустым. Документация Altegio указывает, что длительность может быть доступна только при фильтре по сотруднику. Запросы по каждому специалисту и вывод демодлительности для заполнения поля не входят в этап. Убрать демоплашку именно с фактов реальной услуги.
- Фото берётся из публичного HTTPS-поля, затем из утверждённой по реальному ID локальной иллюстрации, затем из нейтральной заглушки. Поддержать неудачную загрузку. Для `sports` подтвердить право использовать прежнее фото как иллюстрацию и явно сопоставить его с реальным ID, если такое решение уже принято. Одноимённый slug сам по себе не подтверждает соответствие изображения.
- Сохранить кнопку «Записаться» на реальной странице, включая текст, оформление и положение. Пока форма работает с демокаталогом, вывести кнопку без `href`, перехода или предзаполнения. На сохранённых демостраницах оставить действующую кнопку с демопредзаполнением. В части 1 сохранить блок специалистов на его месте без подстановки сотрудников из демокаталога. У `sports` сохранить существующую сетку и прочие редакционные блоки с их текущей маркировкой.
- Подключить `generateMetadata` и ветку `service` в `PageLd` к той же услуге, которая показана в hero. Сохранить canonical, hreflang RU/EN, `x-default` и `noindex`. Убрать из метаданных реальной услуги жёстко заданные AED и обещание онлайн-записи. JSON-LD описывает реальную услугу и её канонический путь. Если добавляется `Offer`, использовать подтверждённую цену и валюту и URL detail-страницы, без `?service=` и ссылок на демозапись. Проверить, что существующие записи sitemap для detail-адресов остаются каноническими. Полную миграцию sitemap каталога оставить до миграции списков.

### Приёмка части 1

- RU/EN для `sports` и новой синтетической услуги без редакционного slug. Проверить прямой URL без пересборки, совпадение hero, API и метаданных по идентичности услуги, смену языка, переносы длинного заголовка, неизвестную категорию, неполные поля, нулевую цену, диапазон и нерабочее фото.
- API различает неверный query, неизвестную услугу и временный сбой каталога. Проверить корректные статусы, отсутствие демоданных на реальном адресе при сбое и восстановление после повтора. Проверить переходы из `/services` и `/prices`. На реальной странице кнопка записи видна, у неё отсутствует `href`, нажатие не выполняет переход и не меняет данные записи в `sessionStorage`. На сохранённой демостранице кнопка по-прежнему передаёт демопредзаполнение.

## Часть 2. Специалисты выбранной услуги

1. Использовать публичный Online Booking API v1 `GET /book_staff/{location_id}?service_ids%5B%5D=<id>` с одним ID уже разрешённой публичной услуги. В спецификации параметр называется `service_ids[]`, `style: form`, `explode: false`. Для одного значения удобно использовать `URLSearchParams`. Запросить без `datetime`: это публичная связь с услугой, расписание и ближайшие окна в этом этапе отсутствуют. Параметр `without_seances` для `book_staff` не документирован. Сохранить Partner Token, `Accept` и `Accept-Language` по текущему транспорту. [Официальная спецификация Altegio Online Booking](https://developer.alteg.io/en/public/openapi)
2. Перед выводом людей сверить результат фильтра на двух публичных услугах с известным различием в назначении, если доступен филиал. Сравнить с ожидаемым назначением и с ответом без фильтра. Пустой результат допустим. Если параметр игнорируется или фильтр не отражает связь для этого филиала, зафиксировать расхождение и показать состояние недоступности блока до подтверждения источника связи. В качестве диагностической сверки для известного сотрудника допустим `book_services` с `staff_id` и `without_seances=1`. Не делать такой обход для каждого сотрудника при открытии страницы. Без настроенного филиала выполнить сценарии на fixture и указать, что живая сверка ещё нужна.
3. Переиспользовать транспорт, существующую нормализацию и `CatalogStaffMember`. Сохранять порядок Altegio, исключать `hidden: 1` и `fired: 1`, не исключать автоматически `bookable: false`. Из ответа использовать только публичные поля DTO. Кеш списка по услуге учитывает филиал, локаль и ID услуги. Переиспользовать ревалидацию 14400 секунд, объединение запросов и обработку `Retry-After`. Общий `GET /api/catalog/staff` и секция команды на главной сохраняют текущий контракт и не получают фильтр страницы.
4. Оставить API части 1 независимым от списка сотрудников. Если нужен отдельный HTTP-ресурс для этого списка, использовать `GET /api/catalog/services/[slug]/staff?locale=ru|en` с теми же правилами разрешения slug, `404` для неизвестной услуги и `200` с пустым `staff` для существующей услуги без специалистов. Страница вызывает общий server-only загрузчик напрямую. Разрешать публичную услугу до обращения к `book_staff`.
5. Показать сотрудников в одном блоке `.doc-sections__wide` с заголовком `service.section.specialists`. Для `sports` сохранить положение в существующей сетке. Для остальных реальных detail-страниц использовать тот же полноширинный блок. В карточке показать публичное имя, фото с обработкой сбоя и доступную должность или специализацию, если она нужна в текущей карточке. Использовать существующие `StaffCard` и правила фото этапа 3. До подключения реальных страниц команды имя и прочие элементы карточки остаются видимыми, а `href` профиля отсутствует. Показать самостоятельные состояния загрузки, пустого списка и ошибки с повтором. Сбой или медленный ответ блока не затрагивает hero и данные услуги.

### Приёмка части 2

- Синтетический upstream получает один `service_ids[]` с реальным ID из DTO без даты. Разные услуги получают разные списки и кеши. Неизвестный slug не вызывает `book_staff`. Услуга без специалистов, скрытый сотрудник, `bookable: false`, ошибка и повтор проверяются отдельно. При медленном upstream hero виден до завершения блока.
- Проверить локализацию, переключение услуги, стабильный порядок, фото и поведение карточек в мобильной и широкой разметке. Убедиться, что общий API сотрудников, главная и демофлоу записи не регрессировали. Браузер обращается к сайту и публичным фотографиям, а обращения к Altegio API остаются на сервере.
