## 4. Пропущенные тесты

Пропущенный тест — тест, который начал выполняться и сам снял себя по условию, записанному в его коде (`test.skip(условие, причина)`). В полных прогонах пропущено 326 тестов из 1147 на `main` и 350 из 1178 на `482b790`.

**Разложение по причинам с числами есть для шести профилей телефонов из восьми** — из отчёта Playwright в формате JSON, который записал запуск 2 на `071c230` (раздел 2). Для остальной части набора (страницы, `flows`, `A-iphone-se`, `A-iphone-13mini`) такого отчёта нет: он пишется в конце прогона, а запуск 1 оборвался. Для неё ниже — причины по коду проверок и то, что о числах известно из журналов.

Шесть профилей (`A-iphone-16`, `A-iphone-17promax`, `A-moto-g4`, `A-pixel-9`, `A-pixel-7`, `A-galaxy-a`), 540 тестов, пропущено 265:

|---|---|---|
| Логика отслеживания лендинга идёт только в проекте `flows`: 19 тестов × 6 профилей | 114 | `lp-tracking.spec.ts` |
| Проверка выполняется один раз на движок или в одном названном проекте | 122 | `lp.spec.ts` 60, `mobile.spec.ts` 32, `hero.spec.ts` 25, `booking-compact.spec.ts` 5 |

Все 265 — пропуски по замыслу: тот же тест выполняется в проекте, для которого он написан. Пропусков из-за того, что на машине не показалась 3D-модель, в этих шести профилях нет.

Откуда разница 350 − 326 = 24. В RC-9 добавлено три теста логики отслеживания лендинга (`e2e/lp-tracking.spec.ts`). Они рассчитаны на один проект, `flows`, а в восьми профилях телефонов снимаются по условию: 3 × 8 = 24. Остальные новые тесты RC-9 идут в `flows` и прошли: 828 − 821 = 7.

Причины пропуска во всём наборе — двух родов.

**По замыслу: тест адресован другим устройствам или размерам.** Это не пробел в проверке — тот же тест выполняется в проекте, для которого написан.
